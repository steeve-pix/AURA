# AURA v0.3.0-rc.1

This release candidate brings the accumulated 3D simulation, learning and terminal
workspace changes through `dev` into `main`. It preserves the research history;
it is not a stable balancing policy or a general body-stability guarantee.

## Included

- Humanoid joint, contact, ground-motion and body diagnostics, with versioned
  simulation observations, actions, rewards and termination contracts.
- Independent simulation workers, actor/critic checkpoints, retained training
  history, configurable network designs and bounded matched experiments.
- Model creation, experiment setup/training/audits/comparisons/runs, component
  charts, direct experiment renaming and saved-record compatibility checks.
- Live critic rollout progress, contextual training loading screens, corrected
  independent-critic compatibility, and improved terminal navigation and dialogs.
- Source, tests, research results and traces organized into their documented
  subsystem folders. Historical replays and evidence remain available.

Local trained models, generated experiments/reports, build products, virtual
environments and IDE state are excluded. Existing checkpoints are not rewritten
by this release preparation. The project tag and CLI's own version are separate.

## Known limitations

- The pre-existing `joint` test still fails `foot remains attached to shin` in
  its isolated four-part-chain scenario. The first reported failure is at step
  186 (1.55 simulated seconds), with an ankle-anchor gap of approximately
  0.00447 against the existing 0.001 limit. The test remains enabled and failing;
  no tolerance, solver budget, damping or motor setting was changed to hide it.
  Passing the application runtime baseline does not invalidate this failure.
- Long actor training can regress and lose earlier balance improvements. Best
  checkpoints are retained, but successful, repeatable standing has not been
  demonstrated. Experiment execution tests do not establish learning quality.
- Some historical artifacts use older environment/reward contracts and remain
  incompatible with current training. Read-only inspection preserves provenance.
- The development Python environment has no NumPy installed. Tensor-only CLI
  paths work; optional NumPy startup warnings can appear in the test harness.
- Debug suites were not rerun for this release preparation. Prior measurements
  are historical evidence, not fresh verification of this tag.

This tag records an inspectable development checkpoint with these limitations;
it deliberately does not mark the physics test suite or learned agent as stable.
